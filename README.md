# ypbank-tools

Учебный проект для чтения, конвертации и сравнения финансовых операций. Один Cargo-пакет содержит библиотеку и приложения `converter` и `comparer`. Библиотека работает с потоками `Read` и `Write` и поддерживает форматы `csv`, `text` и `bin`.

## Запуск

Нужен Rust с поддержкой edition 2024. Команды выполняются из каталога проекта.

```sh
cargo run --bin converter -- csv text input.csv
cargo run --bin comparer -- csv input.csv text input.txt
```

Конвертер принимает входной и выходной форматы, затем необязательный путь к файлу. Без пути он читает стандартный ввод. Результат выводится в стандартный вывод.

```sh
cargo run --bin converter -- csv text < input.csv > output.txt
```

Для бинарного вывода используйте перенаправление, сохраняющее байты без преобразования, например в командной строке Windows `cmd.exe`.

```bat
cargo run --bin converter -- csv bin input.csv > output.bin
```

`comparer` принимает формат и путь для каждого файла. Он сравнивает разобранные транзакции по порядку и сообщает о первом отличающемся поле или лишней записи. Позиции начинаются с 1. Код завершения равен 0 при совпадении, 1 при различии и 2 при ошибке.

## Форматы

CSV начинается с точного заголовка `date,category,kind,amount`, после которого следует одна операция на строку. В `text` заголовка нет, а поля разделяются точкой с запятой.

```text
date,category,kind,amount
2026-04-01,salary,income,120000
```

```text
2026-04-01;salary;income;120000
```

Текстовые форматы используют UTF-8 и простой разбор по разделителю. Кавычки и экранирование не поддерживаются, поэтому поля не могут содержать разделитель или перевод строки. Дата должна быть действительной и иметь формат `YYYY-MM-DD`, тип операции — `income` или `expense`, сумма — целое число от 0 до 4294967295 в копейках.

## Бинарный формат

Все многобайтовые числа записываются в порядке little-endian. Файл начинается с количества транзакций как `u32`. Затем идут записи в исходном порядке. Каждая запись содержит следующие поля.

1. Дата — длина в байтах как `u32`, затем байты строки в UTF-8.
2. Категория — длина в байтах как `u32`, затем байты строки в UTF-8.
3. Тип операции — один байт, `0` для `income` и `1` для `expense`.
4. Сумма в копейках — `u32`.

Отдельного заголовка и версии формат не содержит. Чтение завершается после указанного числа записей, оставшиеся байты не проверяются.
